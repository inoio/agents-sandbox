Docker in the sandbox now runs rootless, as the `dev` user, instead of as root with `dev` in the `docker` group. A
  container can no longer gain root inside the sandbox: mounting `/` does not expose root-only files, and `--privileged`
  stays inside the engine's user namespace. The `docker` command and `/var/run/docker.sock` keep working. Per-container
  resource limits (`--memory`, `--cpus`) are no longer enforced, privileged tooling such as Docker-in-a-container stops
  working, and images built by the previous root engine are not carried over. A custom base image that enables Docker
  must now also provide `uidmap`, `slirp4netns`, and `iproute2`; the image build names any that are missing (#487).
