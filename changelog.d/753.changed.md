`make check` (and `make verify`) now prints one line per target with the target's runtime, the CPU seconds its process tree consumed, and its `[heavy]`/`[light]` lane (`PASS lint 17s (cpu 34s) [heavy]`), ends with a `check: <n> targets in <t>s` total, and on an interactive terminal keeps a live status line on the last row naming the currently-running targets grouped as `heavy`/`light`, redrawn in place and truncated to the terminal width. `CHECK_PROGRESS=1`/`0` forces the status line on or off; it stays off under `VERBOSE`, where the pool streams. `validate-fmt` moves from the serial heavy set into the light pool: it runs a formatter with no type-checking, so it neither saturates cores nor shares build state with `lint`/`test`/`compile-all`. The `*-test` harness targets leave `CHECK_TARGETS`: `test` already runs the whole `test/scripts` package, so `make check` was executing it twice; they remain defined and are still selected by the fast loop; CI names a subset in its `lint` job and covers the rest through the `test` job.
