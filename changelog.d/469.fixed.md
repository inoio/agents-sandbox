A bare checkout whose `core.bare` git moved into the per-worktree `config.worktree` — which happens once
  `extensions.worktreeConfig` is enabled, for example by a sparse worktree — is now still detected as bare, so project
  config is read from the bare root next to `.git` rather than from the launched worktree. The per-worktree file is
  consulted only while `extensions.worktreeConfig` is enabled, matching git, so a file left behind after the extension
  is turned off no longer makes the launcher treat a repo as bare.
