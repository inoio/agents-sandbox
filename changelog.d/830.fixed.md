The memory-limit raise after an OOM is now offered in the session that hits it on runtimes that
report no live metrics: the offer falls back to the memory the run applied for its basis instead of
recording the hit and deferring to the next launch. The post-attach memory and disk offers now build
on the limits the run applied, so a raise accepted while planning is not overwritten by the stale
configured value. A skipped, unclaimed, or already-answered offer is now explained at verbose level.
