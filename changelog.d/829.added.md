Add `make kvm-agent-up`, a one-command bring-up for the KVM-guest agent session: it ensures the guest is running
(idempotent over a created, stopped, or running guest), waits for cloud-init, syncs the checkout, materializes the agent
config, and attaches — reading `LITELLM_API_KEY` from the host environment (extend the credential set with `KVM_AGENT`).
When the agent's session already runs it reattaches without syncing, so re-running it to recover a dropped connection
cannot overwrite the live agent's work. The step-by-step `kvm-up`/`kvm-sync`/`kvm-agent-provision`/`kvm-agent` targets
stay.
