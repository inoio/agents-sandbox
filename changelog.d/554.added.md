Detect a project VM memory-limit hit and offer to raise the persisted `memory` setting. The guest kernel OOM line
(primary) and the session metrics watcher's headroom (fallback) feed one shared detector; an accepted raise is written
to the config layer that owns `memory` (keeping the file's format and permissions) and applies at once when offered at
launch or on the next run when offered after a session, a non-interactive run records the hit for the
next interactive launch, and an answered offer is not repeated. The launcher also emits a terminal reset after an
abnormal attach end, so an OOM-killed TUI leaves no alternate-screen or mouse residue (#544).
