`config harden` audits your effective launcher configuration and applies the risky parts through the same apply engine
a learning session uses, without starting a sandbox. It is re-runnable, writes nothing non-interactively or under
`--dry-run`, and emits only config-only findings: it moves a static secret committed in the project scope to the
per-slug user scope, narrows an over-broad network posture or secret scope, drops a wildcard egress entry, fixes an
`env.secret.yaml` whose mode is too broad, turns off host-config provisioning, and moves a secret left inline in a
managed agent config into `env.secret.yaml`.
