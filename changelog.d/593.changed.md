Pruning is now two tiers: auto-prune and batch `prune` reclaim only artifacts with no user data behind them — stale VMs,
runner images, dangling Docker images, runtime RAM, and stale internal state (including emptied state subtrees) — and
never remove a home volume, so `prune --yes` can no longer destroy agent state. Batch `prune` instead lists retired
projects (no kept sandbox, aged) and points at the new `prune --purge [<slug>|<slug>-<agent>]` (and
`sandbox remove --purge`) to remove a project's VMs, home volumes, runner images, state and claims in one confirmed
pass; a project's home volume is removed only when the target owns it (by name, state reference, or adoption claim), so
purging a legacy slug never deletes another checkout's saved home — ownership is re-derived at execution under the
root lock, so a volume another checkout adopts after the confirmation prompt is refused and a surviving volume keeps
its adoption claim — while `volume prune` removes only volumes no state references. Retired-project attribution
follows ownership too: a claimed volume is credited to its checkout even when a lost-state adoption left no state. Docker images and msb image details now honor `--older-than` and appear only when the runtime actually
deleted them, show in `--dry-run` and `--format json`, task sandboxes are age-exempt in `sandbox prune`, and a
non-positive `--older-than` is rejected.
