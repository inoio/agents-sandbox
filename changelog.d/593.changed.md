Pruning is now two tiers: auto-prune and batch `prune` reclaim only artifacts with no user data behind them — stale VMs,
runner images, dangling Docker images, runtime RAM, and stale internal state — and never remove a home volume, so
`prune --yes` can no longer destroy agent state. Batch `prune` instead lists retired projects (no kept sandbox, aged)
and points at the new `prune --purge [<slug>|<slug>-<agent>]` (and `sandbox remove --purge`) to remove a project's VMs,
home volumes, runner images, state and claims in one confirmed pass; `volume prune` removes only volumes no state
references. Docker images and msb image details now honor `--older-than`, show in `--dry-run` and `--format json`, task
sandboxes are age-exempt in `sandbox prune`, and a non-positive `--older-than` is rejected.
