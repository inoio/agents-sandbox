A live `--memory` decrease the runtime does not apply is now reported as not applied, instead of being reported as
applied while the guest keeps the larger memory. The resize is confirmed against the live limit, with the live limit
as the reference for direction: a limit above the request is a decrease the runtime never unplugs, reported not
applied from the first read; a limit at the request is applied; a limit below it is a raise, polled to the deadline.
The live limit is used because the saved config can lag it, so a request between them is no longer mistaken for a
raise the larger limit already satisfies. Every metrics read is bounded, and a read error or an unknown live limit is
surfaced as unconfirmed rather than as not applied (#661).
