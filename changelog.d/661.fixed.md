A live `--memory` decrease the runtime does not apply is now reported as not applied, instead of being reported as
applied while the guest keeps the larger memory. The resize wait is direction-relative: a raise is satisfied by a
live limit already at or above the request (another client may hold a larger one), otherwise it is polled to the
deadline; a decrease still above the request is reported not applied from the first read, while one already satisfied
succeeds. Every metrics read is bounded, and a read error is surfaced as an unconfirmed read rather than as not
applied (#661).
