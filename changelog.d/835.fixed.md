Turning `provision-host-config` off no longer deletes the agent's in-VM instruction, skill, theme, or plugin files: the stale-removal pass now targets only the config and credential files the launcher manages, and the first-run host seed skips a config-named file found inside a content tree. opencode's broad `**` provision rule is narrowed to the top level of its config dir, so a config-shaped file it also selects under `skills/`, `themes/`, or `plugins/` is neither removed nor seeded over the agent's real config.
