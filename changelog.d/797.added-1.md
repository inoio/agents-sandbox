Add `docker-ready-timeout` and `daemon-ready-timeout` config keys (with `--docker-ready-timeout` / `--daemon-ready-timeout` flags and `AGENTS_SANDBOX_DOCKER_READY_TIMEOUT` / `AGENTS_SANDBOX_DAEMON_READY_TIMEOUT` env vars). They override the readiness timeouts for the in-VM Docker engine and the agent serve daemon, so a slow host — a nested KVM guest — can give a VM start a larger budget. Defaults are unchanged (30s and 60s); `0` uses the built-in default and a negative value is rejected.
