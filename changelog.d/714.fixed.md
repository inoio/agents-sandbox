A done notification for an `opencode2` session no longer fires while a subagent it spawned is still running, or while
one of its background commands is still running: only a session fully at rest alerts, and the genuinely-quiet done
arrives as the session's later execution-succeeded event (#711).

Notification wording is now shared by `opencode` (v1) and `opencode2`: titles use the `agents-sandbox:` prefix
(`agents-sandbox: agent done` / `input requested` / `session error`, a done with pending work appending its reasons)
and the body names the session as `in session '<title>'`, replacing each agent's previous per-agent wording.
