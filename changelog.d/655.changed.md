CI: the `changes` gate's non-code path list is now held in sync across `ci.yml`, `mutation.yml`, `codeql.yml`, and
`check-changelog.sh` by a new `ci/check-ci-guards.sh` gate — which also fails a `github.event_name` condition naming an
undeclared event and an `on.pull_request.types` list that drops a default — the workflows are linted with `actionlint`,
the `changes` job is skipped on a merge group where nothing reads its output, `scripts/changed-targets.sh`'s
fail-safe target set is read from the Makefile's `CHECK_TARGETS`, and `.agents-sandbox/` (the dev VM) joins the non-code
set, so a dev-VM-only change no longer requires a changelog fragment or runs the integration/vulncheck/CodeQL jobs.
