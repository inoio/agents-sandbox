Add the KVM-guest agent workflow: `make kvm-agent` opens a durable agent session (opencode2) in the libvirt guest, where `/dev/kvm`, docker and `msb` work, so the agent can build the launcher and run the `msb` suites; `make kvm-agent-provision` materializes that agent's provisioned config into the guest home. It reuses a new `agents-sandbox config provision` command, which writes the config a sandbox would receive (merged snippets, mirror, host drop-in, home files) into a directory instead of a VM. Provisioning also copies the host's `~/.gitconfig` into the guest (with signing disabled
there) so the agent can commit as the host user, and `make kvm-sync-back` fetches the guest's branches back to the host —
every branch into `refs/remotes/kvm-guest/*`, or one into the local branch of the same name.
