Docker in the sandbox now runs rootless, as the `dev` user, instead of as root with `dev` in the `docker` group. A
  container can no longer gain root inside the sandbox: mounting `/` does not expose root-only files, and `--privileged`
  stays inside the engine's user namespace. The `docker` command and `/var/run/docker.sock` keep working, but `dev` is
  no longer in a `docker` group, so tooling that checks for that group or for a `root:docker` socket needs adjusting.
  Per-container resource limits (`--memory`, `--cpus`) are no longer enforced, and privileged tooling such as
  Docker-in-a-container stops working. The engine keeps its data in `/var/lib/agents-sandbox/docker`; images,
  containers, and named volumes created by the previous root engine are not carried over. A `data-root` in your
  image's `/etc/docker/daemon.json` is still honoured but must be writable by `dev`. A custom base image that enables
  Docker must now also provide `uidmap`, `slirp4netns`, and `iproute2`; the image build names any that are missing
  (#487).
