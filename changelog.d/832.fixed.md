Learn mode: the first-run host seed and the after-run write-back refuse a config file that still holds a credential they
cannot replace by a placeholder: header values, URL userinfo and query secrets, credential flags and `NAME=value`
arguments, tokens in comments, numeric passwords, and any env or header table entry not known to be configuration.
Previously such values were copied verbatim into managed config and the sandbox (#820). A native scalar the parser
resolved from an unquoted spelling — a date under a password, PIN, or key decodes to a timestamp — is refused like its
quoted form, and a credential flag spelled with an underscore (`--api_key`) or an assignment after `-e` inside a single
command string is caught like its hyphenated args-list form. A bare upper-case word in a table or list nested under an
`env`/`headers` table counts as a literal rather than an environment-variable reference. A YAML document-start marker is
no longer mistaken for a second document: a config that opens with `---` after only blank lines and comments is a single
document and is copied like any other, while a file with a real later document — a second `---` even when the first
document is empty, or a `...` end marker after its content — is still refused. The document scan splits on every line
break the YAML decoder honours, so a second document is refused however its lines end.
